# MediaTracker 使用與技術文件

MediaTracker 是管理小說、漫畫與動畫紀錄的 Chrome 擴充功能。使用者在管理面板中維護作品、觀看進度、資源網址及心得，資料儲存在目前瀏覽器的本機擴充功能儲存區。

## 1. 開啟與基本操作

專案使用原生 HTML、CSS 與 JavaScript，不需要建置流程或套件安裝步驟。開發時可在 Chrome 擴充功能管理頁開啟開發人員模式，載入包含 `manifest.json` 的專案資料夾。

點擊擴充功能圖示，再按「開啟管理網頁」，會開啟新的管理面板分頁。左側是作品目錄，右側包含常用網址、篩選條件及作品清單。

| 操作 | 行為 |
| --- | --- |
| 右下角 `+` | 開啟新增作品表單 |
| 作品上的「編輯」 | 修改內容，按「儲存」才寫入資料 |
| 作品上的「刪除」 | 確認後刪除作品 |
| 點擊作品標題 | 複製原始作品名稱到剪貼簿 |
| 作品上的 `▼` | 展開或摺疊作品，保留標題列 |
| 「全部展開／全部摺疊」 | 設定所有作品，包括被篩選隱藏的作品 |
| `A−`／`A+` | 切換 `sm`、`md`、`lg`、`xl` 四種字級並儲存設定 |

新增作品會插在目前瀏覽作品的後方；沒有可用的目前作品位置時，放到完整清單最前方。

作品編輯視窗開啟時會鎖定背景捲動。透過取消、關閉符號或背景離開時，如果表單有變更，會詢問是否放棄儲存。常用網址及 Tag／載體管理視窗沒有同樣的未儲存提醒。

## 2. 作品內容

### 基本欄位與日期

每筆作品可包含標題、觀看開始與結束時間、其他名稱、原作載體、Tag、相關作品、筆記與心得。標題必填，其餘可留白；其他名稱與 Tag 可新增多筆。

日期可手動輸入或透過日曆選取。日曆選取後顯示為 `YYYY/M/D`，空白欄位可直接選今天，清空後也可再次選取。文字與日曆同步時可辨識斜線或連字號格式，兩位數年份會補為 `20xx`。

日期仍是文字欄位，儲存時沒有嚴格日期驗證，也不檢查開始時間是否早於結束時間。清單中的空白日期以 `??` 顯示。

### Novel、Comic 與 Anime 進度

同一作品可同時記錄三種類型，每種類型都有獨立的進度列表與 URL 列表。進度由「說明」及「進度值」組成，可選建議說明或輸入自訂文字。

| 類型 | 預設說明與顯示順序 |
| --- | --- |
| Novel | 文庫、Web 翻譯、Web 原作 |
| Comic | 第 N 話、單行本、番外篇 |
| Anime | 第 N 季、第 N 集、番外篇、電影 |

符合預設說明的項目依上表排序，自訂說明排在後方。顯示及開啟編輯表單時都會套用排序，目前沒有進度列拖曳排序功能。

| 說明 | 輸入範例 | 清單顯示 |
| --- | --- | --- |
| 第 N 話 | `170` | 第 170 話 |
| 第 N 集 | `170` | 第 170 集 |
| 第 N 季 | 季數 `2`、集數 `8` | 第 2 季 第 8 集 |
| 文庫 | `12` | 文庫：12 |

「第 N 季」提供獨立的季數、集數欄位，儲存為逗號分隔字串，例如 `2,8`。只有季數時顯示季數；缺少季數但填了集數時，以 `?` 表示未知季數。修改一般說明不會清空既有進度；切換季／集欄位格式時也會保留原值，切換後可再調整。

### 資源網址與常用網址

作品的 URL 列表可新增多組描述與網址；網址空白的列不會儲存。連結會在新分頁開啟。

面板上方的「常用網址」可展開或收起。「編輯常用網址與網域對照」可分別管理 Novel、Comic、Anime 的網址、顯示名稱及是否顯示，並在同一類型內拖曳排序。完成後需按「儲存所有設定」。

作品網址的顯示名稱取自常用網址：比對 hostname 時去掉前綴 `www.`，找到相同網域後採用第一個符合項目的名稱，否則顯示網域。比對範圍包含三種類型，隱藏的常用網址仍參與名稱比對。

介面雖然寫著「網域對照」，實際是使用常用網址清單對照，沒有獨立的 `domainMaps` 編輯介面。URL 是文字欄位，建議填寫包含 `https://` 的完整網址。

### 文字格式

相關作品、筆記與心得支援簡易格式化；標題、Tag、其他名稱及進度等欄位也會使用相同或部分格式化邏輯。

| 語法 | 效果 |
| --- | --- |
| `[名稱](https://example.com)` | 超連結，只辨識 HTTP／HTTPS 網址 |
| `- 項目` 或 `* 項目` | 無序列表，前導縮排可產生巢狀列表 |
| `~~文字~~` | 刪除線 |
| `~文字~` | 下標 |

程式另會調整中英文與數字間距、將一般文字中的半形冒號轉為全形冒號，並整理部分標點周圍的空白。這不是完整 Markdown 解析器，沒有粗體、標題、程式碼區塊或表格語法的完整支援。

## 3. 篩選與分類管理

選好條件後按「搜尋」套用，按「清空條件」還原完整清單。目前沒有依標題或內文搜尋的文字輸入框。

| 條件 | 判斷方式 |
| --- | --- |
| 原作載體 | 多選時符合其中一個即可；未填載體歸為 `Unknown` |
| 作品類型 | 多選時符合其中一個即可；該類型有進度或 URL 就視為符合 |
| Tag | 必須包含所有選取的 Tag |
| 不同條件組合 | 同時符合各組已選條件 |

原作載體與作品類型是兩個獨立概念。例如原作為 Novel 的作品，也可以因為記錄了動畫進度而符合 Anime 篩選。編輯、排序等操作重繪清單時，也會使用當下選取的篩選條件。

「Tag 管理」及「載體管理」列出全域項目和作品中已有的值，可新增、改名或刪除。按「儲存變更」後，改名同步套用到所有作品；刪除 Tag 會移除作品上的該 Tag，刪除載體會清空作品的該載體欄位。作品表單中新增的 Tag 與載體也會加入全域建議清單。

## 4. 作品排序與左側目錄

作品可用 `▲`／`▼` 移動，或拖曳標題列調整位置，結果立即儲存。篩選時，上下移動以相鄰的可見作品為基準，並調整完整資料順序；拖曳到可見清單末尾會將作品放到完整清單末尾，包括被篩選隱藏的作品之後。

目錄只列出符合篩選的作品，數字表示作品數，不計入書籤。點擊目錄作品可捲動到對應內容；主頁捲動時，會依視窗中央附近的作品更新目錄高亮，並讓該項目在目錄中靠近中央。

目錄有獨立捲動區域，高度依其在瀏覽器視窗中的位置調整，扣除頁首占用的空間及底部留白。

### 分組書籤

書籤是插在目錄作品之間的命名標記，不會建立或移動作品，也不提供分組摺疊。

| 操作 | 行為 |
| --- | --- |
| 「＋ 新增書籤」 | 插入目前瀏覽作品前方；沒有目前作品時使用首個可見作品，沒有可見作品時放在末尾 |
| `✎` | 重新命名，空白名稱不會套用 |
| `×` | 確認後刪除書籤 |
| 拖曳書籤列 | 放到作品或其他書籤之間，藍線表示放置位置 |
| 拖到目錄上下邊緣 | 捲動目錄以尋找放置位置 |

名稱與位置自動儲存。書籤記錄的是「位於哪個作品之前」，因此該作品重新排序時，書籤也會跟隨移動。同一位置可有多個書籤，並可調整彼此順序。

篩選時書籤仍會保留，即使對應作品被隱藏，也可能看見連續的書籤列。對應作品遭刪除，或書籤本來就放在末尾時，書籤顯示在目錄底部。

### 上下邊界吸附

最近完全捲出目錄上方的書籤顯示在頂部；下一個完全位於可視區域下方的書籤顯示在底部。書籤開始進入可視區域時，該書籤的固定提示移除，回到原本的書籤列顯示。繼續捲動時，上下提示切換到新的候選書籤。

固定提示占用獨立空間，不會覆蓋作品。上方沒有捲出的書籤時收起整列，滑回最上方不會留下提示列空白。只要目錄內有書籤，底部仍保留提示空間，避免底部候選切換時反覆改變可視邊界；沒有下方候選時，該處不顯示按鈕。

點擊固定提示可捲動到原書籤位置。提示按鈕可用鍵盤操作，並依系統的減少動態效果偏好選擇是否平滑捲動。改名、刪除與拖曳仍在原書籤列操作。

## 5. 資料保存與備份

資料使用 `chrome.storage.local`，不會自動同步到其他裝置。

| 狀態 | 重新開啟後是否保留 |
| --- | --- |
| 已儲存的作品、作品順序、Tag 與載體清單 | 保留 |
| 常用網址、顯示開關與排序 | 保留 |
| 書籤名稱及位置、字級設定 | 保留 |
| 篩選條件、作品摺疊狀態、常用網址區塊的展開狀態 | 不保留 |
| 未儲存的表單內容、目前捲動位置 | 不保留 |

「匯出資料」下載 `mediatracker_backup_YYYY-MM-DD.json`，包含作品、常用網址、Tag、載體、設定與書籤，以及相容性保留的 `domainMaps`。檔名日期使用 UTC 日期。

**匯入會覆寫備份中提供的儲存欄位，不會合併作品，也沒有覆寫確認步驟。** 建議還原前先匯出目前資料。成功匯入後，面板重新載入。

舊備份若沒有 `bookmarks`，匯入時會將書籤設為空陣列；其他未提供的儲存欄位保留目前值。匯入流程只有 JSON 解析和基本的 `mediaEntries` 存在判斷，沒有完整結構驗證，應優先使用本程式匯出的備份。

讀取舊作品時，進度字串轉為說明為「進度」的單筆項目，URL 字串轉為沒有描述的單筆網址。這是顯示與編輯時的相容轉換，不代表啟動時會將所有舊資料批次重寫。

## 6. 程式架構與資料模型

擴充功能採用 Manifest V3，目前只宣告 `storage` 權限。沒有背景 service worker、content script、伺服器或前端框架。

| 檔案 | 用途 |
| --- | --- |
| `manifest.json` | 設定、權限、圖示及 popup 入口 |
| `popup/popup.html`、`popup/popup.js` | 提供開啟管理面板分頁的按鈕 |
| `dashboard/dashboard.html` | 面板、編輯視窗、資料列模板及建議選項 |
| `dashboard/dashboard.css` | 作品卡片、目錄、書籤提示、表單及字級樣式 |
| `dashboard/dashboard.js` | 渲染、表單、篩選、排序、格式化、書籤及匯入匯出 |
| `js/storage.js` | 本機資料讀取、作品增刪改及設定儲存 |
| `tests/dashboard.test.cjs` | 日期、進度顯示、編輯值保留與未儲存判斷測試 |
| `tests/bookmarks.test.cjs` | 書籤排序、篩選、持久化及邊界候選測試 |
| `tests/sticky-browser.cjs` | 無頭 Chrome 書籤版面與互動驗證 |
| `動漫清單.md` | 獨立 Markdown 檔，管理面板不會自動讀取或匯入 |

`dashboard.js` 使用 `IntersectionObserver` 追蹤主頁作品位置，透過 `ResizeObserver`、捲動事件及 `requestAnimationFrame` 更新書籤提示。書籤排列由 `buildTOCRows()` 和 `moveBookmark()` 處理，邊界候選由 `getBookmarkEdges()` 判斷。

以下型別描述目前寫入的主要資料形狀，不是程式執行時的驗證器。

```typescript
type MediaType = 'novel' | 'comic' | 'anime';

interface MediaDetail {
  progress: { desc: string; val: string }[];
  urls: { desc: string; val: string }[];
}

interface MediaEntry {
  id: string;
  title: string;
  watchingTime: { start: string; end: string }; // 日期文字，可為空
  otherNames: string[];
  tags: string[];
  originalMedium: string;
  novel: MediaDetail;
  comic: MediaDetail;
  anime: MediaDetail;
  relatedWorks: string;
  notes: string;
  thoughts: string;
  updatedAt: number; // 儲存作品時的 Unix 毫秒時間
}

interface Bookmark {
  id: string;
  name: string;
  beforeEntryId: string | null; // null 或不存在的作品 ID 顯示在末尾
}

interface CommonUrl {
  url: string;
  name: string;
  visible?: boolean; // 只有 false 會從常用網址顯示區隱藏
}

interface StoredData {
  mediaEntries: MediaEntry[]; // 陣列順序即完整作品順序
  commonUrls: Record<MediaType, CommonUrl[]>;
  tags: string[];
  mediums: string[];
  bookmarks: Bookmark[];
  settings: {
    fontSizeClass?: 'sm' | 'md' | 'lg' | 'xl';
    fontSize?: number; // 相容欄位，目前畫面使用 fontSizeClass
  };
  domainMaps: Record<string, unknown>; // 保留讀寫與備份，畫面未使用
}
```

## 7. 驗證方式與目前限制

測試使用 Node.js 內建測試工具，不需要安裝 npm 套件。現有測試以 Node.js 24 執行過；日期與表單測試使用簡化 DOM，不能取代 Chrome 原生日曆的手動確認。

```powershell
node --check dashboard/dashboard.js
node --check js/storage.js
node --test tests/dashboard.test.cjs tests/bookmarks.test.cjs
```

書籤版面測試需要本機 Chrome，請使用實際的執行檔路徑：

```powershell
node tests/sticky-browser.cjs 'C:\Program Files\Google\Chrome\Application\chrome.exe'
```

此測試使用模擬作品、獨立暫存瀏覽器設定及本機除錯連線，驗證上下提示、預留空間、點擊定位、滑回頂端及字級／尺寸變化。測試停用主頁作品位置觀察器以控制目錄捲動，不涵蓋整個擴充功能的所有互動，也不會操作使用者的實際作品資料。測試產生的暫存目錄目前不會自動清除。
